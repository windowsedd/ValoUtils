# ts-replay-parser — Claude Code Guide

TypeScript port of [michel-giehl/ValorantReplayParserPlayground](https://github.com/michel-giehl/ValorantReplayParserPlayground)
(itself a fork of [FortniteReplayDecompressor](https://github.com/Shiqan/FortniteReplayDecompressor)).
Parses VALORANT `.vrf` replay files entirely in TypeScript — no native dependency.

> ⚠️ Research / proof-of-concept. Riot's replay format is undocumented and unstable.

## How this package is structured

The port is **bottom-up**: each layer is self-contained and verified against the
original C# before the next is built on top. Read [PORTING.md](./PORTING.md) for the
status table and correctness anchors.

```
src/
  transform/   ValorantSeededPayloadTransform — payload de-obfuscation (BigInt 64-bit math)
  io/          Bit-stream readers: FArchive, BinaryReader, BitReader, NetBitReader + enums/models
  ooz/         Oodle/Kraken (Mermaid) decompressor — port of OozSharp
  unreal/      Replication engine: ReplayReader, NetGuidCache, NetFieldParser, registry, models
  valorant/    Valorant models (registry-driven), ValorantReplayReader, app-parser
  index.ts     Public API barrel
```

Layer dependencies point downward only: `valorant → unreal → {io, ooz, transform}`.
Never introduce an upward import (e.g. `io` importing from `unreal`).

## The one big architectural difference from C#

C# discovered models by reflecting over `[NetFieldExportGroup]` / `[NetFieldExportRPC]`
attributes at runtime. TypeScript has no equivalent, so each model **self-registers a
descriptor** into the shared `registry` (`src/unreal/registry.ts`) at module load.

- Importing `src/valorant/models.ts` populates the registry as a side effect.
- `ValorantReplayReader` imports it, so just constructing the reader wires everything up.
- To add a model: add a class + a `registry.registerGroup({...})` call in `valorant/models.ts`.
  Use `usesHandles: true` for handle-keyed groups (`[NetFieldExportHandle]`).

## Working rules

- **Numbers:** 64-bit reads (`readUInt64`/`readInt64`) return `bigint`. Everything
  narrower is `number`. 32-bit unsigned math is masked with `>>> 0`; 64-bit math uses
  `BigInt` (see `transform/uint.ts`). Don't "simplify" these to plain `number`.
- **Parity is the spec.** When changing reader/transform/decompressor behaviour, verify
  against the C# original — don't eyeball it. The repo's tests work by comparing against
  reference vectors/outputs generated from the C# (`__vectors__.json`, `__replay_refs__.json`,
  `__movement_refs__.json`, `__decompress_refs__.json`).
- **Keep the C# line references.** Many files cite the Unreal/C# source line they mirror.
  Preserve them — they're how the next person re-checks correctness.

## Public API (src/index.ts)

| Export | Purpose |
|---|---|
| `ValorantReplayReader` | Main entry. `new ValorantReplayReader(version?, mode?)` then `.readReplay(bytes)` |
| `ValorantReplay` | Result type: `.Info`, `.Header`, `.exports[]` |
| `parseReplayForApp(bytes, opts)` | App-facing convenience: returns `{ replay, exportRecords, channelOpens }` |
| `ParseMode` | `EventsOnly < Minimal < Normal < Full < Debug` — higher = more parsed |
| `applyTransform` | The seeded payload de-obfuscation (low-level) |
| `decompressReplayData` / `Kraken` | Oodle/Kraken decompression (low-level) |

`version` may be omitted/`null` to auto-detect from the replay header branch
(`++Ares-Core+release-12.11`). `ParseMode.Full` is required for character movement.

See [examples/](./examples/) for runnable usage.

## Verification harness (advanced)

Parity references are generated by tiny throwaway C# programs that reuse the cloned
upstream projects. If you change parsing behaviour and need to regenerate a reference,
that requires the .NET SDK and the upstream clone — ask the user before running it
(executing externally-cloned code is gated). The committed `__*__.json` fixtures are the
source of truth for the tests; treat changing them as changing the spec.

## Known limitation

Only the **local player's** character movement is decoded (a single character GUID per
replay) — this is true of the upstream C# original too, not a port regression.
